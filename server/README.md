# ИИ-прокси NutriBear на Cloudflare Worker — бесплатно

Ключ от ИИ (**sk-…**) больше не зашивается в приложение: он хранится
в секрете Cloudflare, а приложение знает только адрес вашего воркера.
Это снимает блокер для выпуска в магазин: даже разобрав APK/IPA,
ключ никто не достанет.

Здесь же живёт и второй канал — **обращения из окна «Написать нам»**
уходят прямо из приложения на воркер (`POST /v1/support`) и пересылаются
владельцу в **Telegram**: почтовый клиент на телефоне пользователя
не открывается (отзыв Кати 21.11: «я хочу чтобы прямо из приложения
пользователь отправлял обращение»). Токен бота и chat_id — в секретах
Cloudflare, в бандл APK они НЕ попадают.

Хватит бесплатного тарифа Cloudflare Workers: **100 000 запросов
в день**, карта не нужна.

---

## Обращения в поддержку → Telegram (2 минуты, скрипт)

Один раз: создайте бота (Telegram → **@BotFather** → `/newbot` →
имя и username вида `nutribear_support_bot` — он пришлёт **токен**),
напишите боту любое сообщение, затем запустите скрипт из корня
проекта и вставьте токен:

```powershell
.\setup-support.ps1
```

Скрипт сам: проверит токен (getMe), найдёт ваш chat_id (по вашему
сообщению боту), зальёт секреты `TG_BOT_TOKEN` и `TG_CHAT_ID`,
переразвернёт воркер и отправит **тестовое обращение** через реальный
endpoint — оно должно прийти вам в Telegram. Пока секреты не залиты,
приложение само молча откатывается на прежний mailto-поток — ничего
не ломается.

## Деплой одной командой (3 шага)

Нужен только Node.js (уже установлен — Expo работает).

**Самый простой путь — один скрипт из корня проекта:** `.\deploy-proxy.ps1`.
Он сам сделает шаги 1–3: войдёт в Cloudflare, возьмёт ключ из `.env`,
сгенерирует и сохранит секрет `NB_SECRET` (и пропишет его в `.env`),
опубликует воркер и пропишет адрес прокси в `.env`. Останется только
перезапустить Expo (`npx expo start --clear`). Скрипт на английском —
это намеренно (PowerShell 5.1 ломает кириллицу в .ps1).

**Ручной путь (те же шаги по одному):**

**1. Вход в Cloudflare** (один раз; откроется браузер):

```powershell
cd C:\Users\Администратор\Desktop\nutribear-expo\server
npx wrangler login
```

Если аккаунта Cloudflare ещё нет — регистрация на
<https://dash.cloudflare.com/sign-up> занимает минуту (только e-mail).

**2. Сохранить ключ ИИ в секрете** (один раз; вставьте свой sk-… из
ProxyAPI и нажмите Enter — в консоли ничего не отобразится, это норма):

```powershell
npx wrangler secret put AI_KEY
```

**2а. (Настоятельно рекомендуется) Общий секрет приложения.** Без него
POST-запросы к воркеру может слать кто угодно, нашедший адрес. Придумайте
длинную случайную строку и задайте её дважды — на воркере и в .env
(имя переменной там — `EXPO_PUBLIC_AI_PROXY_SECRET`):

```powershell
npx wrangler secret put NB_SECRET
```

**3. Опубликовать:**

```powershell
npx wrangler deploy
```

В ответе будет адрес вида
`https://nutribear-ai.ваш-аккаунт.workers.dev` — это и есть ваш сервер.

## Подключить приложение (одна строка в .env)

В файле `.env` в корне проекта добавьте (адрес из шага 3):

```env
EXPO_PUBLIC_AI_PROXY_URL=https://nutribear-ai.ваш-аккаунт.workers.dev/v1
```

и перезапустите Expo (`npx expo start --clear`).

Всё: чат, распознавание фото еды и голосовой ввод пойдут через ваш
воркер, ключ из `.env` и из приложения больше не нужен
(`EXPO_PUBLIC_AI_KEY` можно удалить из `.env`).

> Пока `EXPO_PUBLIC_AI_PROXY_URL` не задан, чат работает по-старому —
> с веб-версией на ПК разработчика. Ничего не сломается.

## Обновление воркера (после первого деплоя)

Код воркера меняется коммитами, но на Cloudflare он попадает только
после повторного деплоя — он не запускается автоматически. На ПК, где
уже выполнен `deploy-proxy.ps1`, обновление — один скрипт из корня
проекта: `.\update-proxy.ps1` (git pull → `npx wrangler deploy` →
проверка `/v1/status`). Секреты (`AI_KEY`, `NB_SECRET`, `TG_BOT_TOKEN`,
`TG_CHAT_ID`) живут на Cloudflare и при деплое не сбрасываются —
вводить их заново не нужно.

Проверить, что живёт новая версия: откройте
`https://nutribear-ai.popovakatua2013.workers.dev/v1/status` — ответ
должен содержать `secret_required`, `key_set` и лимиты (у старой версии
там только `{"ok":true,"service":"nutribear-ai"}`).

---

## Проверка

Откройте в браузере `https://nutribear-ai.ваш-аккаунт.workers.dev` —
должно быть `{"ok":true,"service":"nutribear-ai"}`.

Проверка чата из консоли:

```powershell
curl.exe -X POST "https://nutribear-ai.ваш-аккаунт.workers.dev/v1/chat" -H "Content-Type: application/json" -d "{\"messages\":[{\"role\":\"user\",\"content\":\"сколько пить воды?\"}]}"
```

Логи вживую: `npx wrangler tail`.

## Как это работает

```
Приложение ──POST /v1/chat { messages }──▶ Worker ──ключ из секрета──▶ ProxyAPI
        ◀────── { reply } ────────────────┘ ◀──────── ответ ──────────┘
```

| Путь воркера              | Кто пользуется                       |
| ------------------------- | ------------------------------------ |
| `POST /v1/chat`           | ИИ-чат в приложении                  |
| `POST /v1/chat/completions` | Фото еды и фразы (OpenAI-протокол) |
| `POST /v1/audio/transcriptions` | Голосовой ввод дневника        |
| `GET /`                   | Проверка «жив ли» из браузера        |

Смена модели чата — правка `AI_MODEL` в `wrangler.toml` + повторный
`npx wrangler deploy`. Смена поставщика — `AI_UPSTREAM` там же.
